# Testing Deliverables

Everything in this directory except this file is **generated**. It is produced
by the [testing repository](https://github.com/TeamNova-SRI-KO-LMS/testing) and
imported here by `npm run sync`, which prepends a provenance banner to each
copy.

```bash
# in the testing repository
npm run coverage      # runs unit + integration + security + frontend, merges coverage
npm run report:all    # regenerates register, traceability, endpoints, OWASP

# in this repository
npm run sync          # import the results
npm run sync:check    # CI gate: fails if a committed copy is stale
```

## Why these are copies rather than originals

A test register that is typed out by hand is a snapshot of what somebody
believed the suite did on the afternoon they wrote it. Every row in
`test-register.md` is generated from a `testCase({...})` declaration that sits
directly beside the assertion it describes, and the *Actual Output* and *Status*
columns come from the most recent execution — so the register cannot disagree
with the suite, because it is derived from it.

That property only holds if nobody edits the copy. `npm run sync:check` is the
enforcement: it re-renders each file from source and fails if the committed
bytes differ. Editing a file here to fix a typo will break CI, which is the
correct outcome — the typo is in the generator.

## Reading them in order

Start with [test-strategy.md](./test-strategy.md) — it explains the shape of the
suite and the reasoning behind it. Then:

- **[coverage-sprint8.md](./coverage-sprint8.md)** for the §6.4 gates: 80 % overall,
  90 % on critical business logic, 100 % of endpoints.
- **[traceability-matrix.md](./traceability-matrix.md)** to check a requirement from
  the [SRS](../srs/srs-final.md) against the tests that verify it.
- **[test-register.md](./test-register.md)** for the case-by-case detail.
- **[defect-register.md](./defect-register.md)** for what the suite found and the
  application has not yet fixed. Each entry has a test asserting the *correct*
  behaviour, declared `testCase.failing`, so the build breaks when the defect is
  fixed and the entry has to be retired. A defect here cannot be quietly
  forgotten.
