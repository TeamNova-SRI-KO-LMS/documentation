## Instructions

Rate each team member — **including yourself** — on the criteria below using a
scale of 1–5.

| 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- |
| Poor | Below Average | Average | Good | Excellent |

> **MANDATORY.** All ratings must be justified with written comments. If you
> have supporting evidence (screenshots, CI pipeline logs, commit history,
> emails), attach it in the *Proof / Evidence* section for that team member.

### What counts as evidence

The five criteria are judgements, but they are judgements about things this
project records. Before writing a rating, the evidence is usually already
there:

| Criterion | Where the evidence lives |
| --- | --- |
| Contribution Quality | Merged PRs, review comments left and received, defects found or fixed |
| Commitment & Effort | Commit history across the sprint, issues closed vs. assigned on the Project board |
| Collaboration | PR review turnaround, pairing, answers given in issue threads |
| Reliability | Issues delivered inside the sprint they were committed to; CI left green |
| Initiative | Work picked up that nobody assigned — a flaky test fixed, a defect filed, a document written |

Quote the specific artefact (`PR #42`, `DEFECT-08`, `Issue #117`) rather than a
general impression. A rating with a reference behind it is a judgement; one
without is an opinion.

## How to submit (§10.2)

> **Mandatory individual submission.** Peer evaluations are an individual
> obligation. Each student must submit their own completed form. A missing peer
> evaluation results in a deduction from that student's Continuous Progress
> component. **The team leader's submission does not substitute for anyone
> else's.**

1. Start from this form (or download it from the eKelaniya course page).
2. Complete **all** sections: Self, and one section per team member.
3. Justify **every** rating with a written comment. Attach supporting evidence
   — screenshots, commit logs, CI reports, meeting notes — where relevant.
4. Save the completed form as a PDF named exactly:

   ```text
   PeerEval_<StudentNumber>_SENG34213.pdf
   ```

5. Submit the PDF through the designated link on eKelaniya:
   <https://ekel.kln.ac.lk/> → **SENG 34213** → **Assessments** → **Peer
   Evaluation Submission**.

**Deadline.** Within **48 hours** of the Final Product Demonstration. Late
submissions are not accepted without prior written approval from the supervisor.

**Confidentiality.** Responses are seen only by the academic supervisor and are
never shared with teammates. Completed forms must **not** be committed to this
repository — they contain personal assessments of named individuals, and this
repository is shared with the whole team.

---

## Producing the PDF

```bash
npm run build:pdf -- documents/forms/peer-evaluation-form.md
```

That writes `build/pdf/peer-evaluation-form.pdf`, which can be filled in
electronically or printed and completed by hand. Either way, the completed file
goes to eKelaniya and **not** into git — `.gitignore` already excludes
`PeerEval_*.pdf` to make that mistake hard to make.
